# Fixtures

Synthetic source-harness repositories used by tests and documentation. Rules:

- **Small and boring.** A fixture exists to pin behavior, not to be a showcase.
- **Synthetic only.** No third-party repository content, no real tokens, no URLs with credentials. `.example.test` hosts only.
- **Committed.** A fixture is the input half of a golden test; the expected output is generated by the test and reviewed in the PR.
- **One behavior per fixture.** `opencode-basic` is the happy path; collision/malformed/auth fixtures isolate the ugly paths.
- **Never mutate during a test run.** Tests copy a fixture into a temp directory before scanning or applying.

| Fixture | Purpose |
|---|---|
| `opencode-basic/` | One local skill with a resource, one configured extra root, one `.agents` already-native skill, one command with `$ARGUMENTS`, one read-only subagent, one disabled remote MCP server, `AGENTS.md` |

The real repository that motivated `dshify` is a manual validation target only and is never committed here.
